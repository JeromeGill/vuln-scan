# Case-insensitive unique names through a generated column

Project names are unique within an organization ignoring case
([S-0001](../stories/0001-projects.md) AC3). The `project` table has a
`name_key` column generated by Postgres as `lower(name)` (stored, never
written by the app) and a unique constraint on (`organization_id`,
`name_key`). The service saves and maps the unique violation to
`CONFLICT`, so two concurrent requests can't both create the name.

Considered instead:

- **A unique index on `lower(name)`.** The natural Postgres answer, but
  TypeORM's `synchronize` can't create an index on an expression (an
  `@Index` with `synchronize: false` would be skipped), and there are no
  migrations yet to create it by hand.
- **A `citext` column.** Needs the `citext` extension, which neither
  `synchronize` nor `synchronizeSchema` creates.
- **Checking for the name in the service before saving.** Racy without the
  constraint, and an extra query.

When migrations arrive, an expression index could replace the column, but
the generated column works the same way and costs one short text per row.
